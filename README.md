# techtoc に記事を出す

このリポジトリは、techtoc に記事を出すときの**置き方の見本**です。

`main` に push すると、techtoc が `content/` の中を取り込んで
サイトを作り直します。**`content/` の外は取り込まれません**
（この README も取り込まれません）。

---

## 1. ファイルの置き方

```
content/
  docs/v1/<lang>/....mdx     ドキュメント（版あり・階層あり）
  handson/<lang>/....mdx     ハンズオン（申し込みができる）
  blog/<lang>/....mdx        ブログ（日付順）
  pages/<lang>/....mdx       単独のページ（会社概要など）
  debug/....py               機器で走らせる原稿（記事ではない）
```

`debug/` だけは**読み物ではありません**。techtoc の管理画面から
USB でつないだ機器へ送って、その場で走らせるための原稿です。
記事と同じように保存・差分・公開の道を通るので、ここで版を管理できます。

- `.py` … MicroPython。**その場で走ります**（焼き込みではありません）
- `.ino` … Arduino。焼く用（ビルドが要るので、実行はまだできません）

**`docs` だけ `v1/` が要ります**（版を持てる作りのため）。
他の 3 つは `<lang>/` から直に始めます。

### URL の決まり方

ファイルの場所が、そのまま URL になります。

```
content/docs/v1/ja/intro.mdx          →  /<会社>/ja/docs/intro
content/docs/v1/ja/guide/setup.mdx    →  /<会社>/ja/docs/guide/setup
content/handson/ja/raspi.mdx          →  /<会社>/ja/handson/raspi
content/blog/ja/2026-08-hello.mdx     →  /<会社>/ja/blog/2026-08-hello
content/pages/ja/about.mdx            →  /<会社>/ja/about
```

拡張子は `.mdx` でも `.md` でも構いません。

## 2. 日本語と英語

**言語はフォルダで分けます。** ファイル名は両方で同じにしてください
——同じ名前どうしが「対訳」として結び付きます。

```
content/docs/v1/ja/intro.mdx     →  /<会社>/ja/docs/intro
content/docs/v1/en/intro.mdx     →  /<会社>/en/docs/intro
                ↑ 同じ名前なので、この 2 つが対訳になる
```

対訳があると、記事の言語切り替えが**同じ記事どうし**で繋がります。
名前が違うと別々の記事として扱われ、切り替えるとトップに戻ります。

### 訳が無いときどうなるか

**片方だけでも出ます。** ただし向きによって挙動が違います。

| 置いたもの | `/ja/` | `/en/` |
|---|---|---|
| ja と en の両方 | ja の内容 | en の内容 |
| **en だけ** | **en の内容が出る**（代替） | en の内容 |
| **ja だけ** | ja の内容 | **出ない** |

代わりが作られるのは、**既定の言語（`en`）の記事だけ**です。
`ja` にしか無い記事は、`en` 側に元が無いので代わりを作れません。

代わりに出ているページには、本文の冒頭に断りが付きます。

> このページはまだ日本語訳がありません。英語の内容を表示しています。

`lang` 属性も英語（`en`）になります。黙って別の言語を出すと、
読み手にも読み上げソフトにも嘘をつくことになるためです。
サイドバーでも、その項目に未訳の印が付きます。

取り込みのときは警告が出ます（**止まりはしません**）。

```
warning: missing translation: content/docs/v1/en/intro.mdx has no `ja` counterpart
```

この警告が出るのは **`en` にあって `ja` に無い**ときだけです。
`ja` にしか無い記事は（`en` に出ないにもかかわらず）警告されません。

### 下書きと訳の関係（気をつけるところ）

`ja` の記事を `draft: true` にすると、その記事は代わりを作る仕組みから
**無かった扱い**になります。すると `en` 版が代わりとして作られ、
**`/ja/` の URL に英語が出ます**——引っ込めたつもりが 404 にならず、
英語に化けます。

日本語版だけを一時的に引っ込めたいときは、**`en` 版も一緒に
`draft: true`** にしてください。

### どちらか片方だけで始めてよい

**最初は日本語だけで構いません。** その場合、記事は `/ja/` にだけ出ます。
英語を足したくなったら、同じ名前で `en/` に置けば対訳になります。

## 3. `_structure.json`（フォルダの表示名と並び順）

`docs` はフォルダで階層を作れます。**フォルダ名がそのまま
サイドバーに出る**ので、日本語にしたいときや順番を決めたいときに
このファイルを置きます。

### 置き場所は 1 つだけ

```
content/docs/v1/_structure.json     ← ここ。版の直下
```

**言語ごとには置きません。** 階層はどの言語でも同じなので、
ここに 1 回だけ書きます（`ja/` や `en/` の中に置いても読まれません）。

### 書き方

```json
{
  "$comment": "$ で始まるキーは注記。JSON にコメントが書けないため",

  "guide": {
    "position": 1,
    "label": { "ja": "使いかた", "en": "Guide" }
  },
  "reference": {
    "position": 2,
    "label": "Reference",
    "collapsed": false
  }
}
```

**キーはフォルダ名**（`content/docs/v1/ja/guide/` なら `guide`）。
言語の部分は含めません。

| | 型 | 既定 | 何をするか |
|---|---|---|---|
| `label` | 文字列 or 言語別オブジェクト | フォルダ名 | サイドバーの表示名 |
| `position` | 数 | ファイル順 | 小さいほど上 |
| `collapsed` | 真偽 | `true`（畳む） | 初期状態で開くか |

`label` は 2 通り書けます。

```json
"label": "Reference"                        全言語で同じ
"label": { "ja": "リファレンス", "en": "Reference" }   言語別
```

### 任意です

**無くても動きます。** その場合フォルダ名がそのまま表示名になり、
並び順はファイル名順です。

**壊れている（JSON として読めない）と、取り込みが止まります。**
黙って無視すると表示名が全部フォルダ名に化けて、気づきにくいためです。

### 記事の並び順

フォルダの中の**記事**の順番は `_structure.json` ではなく、
記事の frontmatter の `sidebar_position` で決めます。

## 4. frontmatter（記事の先頭）

先頭に `---` で挟んで書きます。**`---` は必ず 2 本**、
1 本目はファイルの 1 行目に置いてください。

```yaml
---
title: はじめに
description: 概要と導入手順
---

本文はここから。
```

### 型の書き方

| 型 | 書き方 | 通るもの |
|---|---|---|
| 文字列 | `title: はじめに` | 文字列・数（数は文字列になります） |
| 数 | `capacity: 12` | `12` / `"12"` / `1.5`。**`12名` は通りません** |
| 真偽 | `draft: true` | `true` / `false` のみ。**`"true"` は通りません** |
| 日付 | `date: 2026-08-12` | 日付として読める文字列（下記） |
| 文字列の配列 | `tags: [a, b]` | 配列、または**文字列 1 つ**（`tags: radius` も可） |

**日付は時刻と時差まで書けます。**

```yaml
date: 2026-08-12                        日付だけ
event_date: 2026-11-14T13:00:00+09:00   日本時間の 13 時
```

ハンズオンの開催日時は**時差まで書いてください**。省くと UTC として
読まれ、9 時間ずれます。

### 値に使えない文字

`:` や `#` を含む文字列は、**引用符で囲んでください**。

```yaml
title: "RADIUS: 認証の仕組み"     ← : があるので囲む
description: '#1 の理由'          ← # があるので囲む
```

## 5. collection ごとの frontmatter

### docs

```yaml
---
title: はじめに              # 必須
description: 概要と導入手順   # 任意（一覧と検索に出ます）
sidebar_position: 1          # 任意（小さいほど上）
draft: false                 # 任意（true にすると出ません）
---
```

### blog

```yaml
---
title: RADIUS の話
date: 2026-08-12             # 必須（新しい順に並びます）
author: 山田                  # 任意
tags: [radius, eap]          # 任意
draft: false                 # 任意
---
```

### handson（申し込みができる回）

```yaml
---
title: ラズパイを RADIUS で認証させる
description: 3 時間で動かします          # 任意
event_date: 2026-11-14T13:00:00+09:00   # 必須
duration_minutes: 180                    # 必須
capacity: 12                             # 必須
venue: オンライン（Zoom）                 # 任意
instructor: 山田                          # 任意
requirements:                            # 任意（持ち物）
  - Raspberry Pi
  - microSD カード
price_yen: 8800                          # 任意（0 なら無料）
payment_url: https://example.com/pay     # 有料なら必須
sidebar_position: 1                      # 任意
draft: false                             # 任意
---
```

**必須が多いのは、申し込みができるためです。** 日時と定員が無いと
席を数えられません。

**有料（`price_yen` が 1 以上）なのに `payment_url` が無い回は
取り込まれません。** 申し込めても払えない状態を作らないためです。

### pages

```yaml
---
title: 会社概要
description: 私たちについて   # 任意
---
```

## 6. 本文の書き方

ふつうの Markdown が使えます。それに加えて 2 つ。

### 見出し

**`# 見出し` を本文に書かないでください。**
frontmatter の `title` が h1 になります。本文は `##` から始めます。

```markdown
---
title: はじめに
---

導入の文章。

## 概要        ← ここから
```

### 注記（callout）

```markdown
:::note
補足です。
:::

:::warning[気をつけること]
角括弧で見出しを付けられます。
:::
```

使えるのは **6 種類だけ**です。

| | 使いどころ |
|---|---|
| `note` | 補足 |
| `tip` | こうするとよい |
| `info` | 参考 |
| `warning` | 気をつけること |
| `danger` | 壊れること |
| `caution` | `warning` と同じ扱い（旧称） |

**これ以外の名前（`:::message` など）は、そのままの文字で出ます。**
色も枠も付きません。

### コード

````markdown
```go
func main() {}
```
````

言語を書くと色が付きます。

---

## 7. 取り込まれないもの

- `content/` の外にあるもの（README・ソース・画像置き場など）
- `draft: true` の記事
- `.mdx` `.md` 以外のファイル
- **`_` か `.` で始まる名前**のファイル・フォルダ
  （書きかけの置き場所に使えます。`_drafts/` など）

---

## 8. 反映されないときは

techtoc の「リポジトリ」の画面に、**最後の取り込みと失敗の理由**が
出ています。よくあるのは次の 3 つです。

**記事が 0 本と言われる**
`content/` の下に `.mdx` がありません。`docs` なら
`content/docs/v1/ja/` まで作れているか確かめてください。

**特定の記事だけ出ない**
`draft: true` になっているか、ファイル名が `_` `.` で始まっているか、
`ja` だけ置いて `/en/` を見ているかのどれかです。

**全部出ない**
どこか 1 本の frontmatter か `_structure.json` が壊れています。
**必須の項目が無いと、その 1 本ではなく取り込み全体が止まります**
——気づかないまま出ていないより、止まって理由が出るほうがよい、
という作りです。理由には**ファイル名が出ます**。

```
content/docs/v1/ja/intro.mdx: missing required frontmatter field `title` (string)
```
